# Studio Dev Workflow (Rojo + MCP)

The **in-Studio developer path** — for visually editing/testing the game in Roblox Studio with live
sync from `src/`. This is separate from the [remote-build rig](OPERATING.md) (the kid's Telegram path,
which never touches Studio). Use this when *you* want to build/inspect/playtest in Studio directly.

> The game's scenery (world, house, dealership, cars) is generated by **server scripts at runtime**, so
> it only appears in **Play (F5)** or **Run (F8)** — not in edit mode. Edit mode shows only the static
> `Ground` + `SpawnLocation`.

---

## One-time setup
```bash
rojo build -o brookhaven.rbxlx && open brookhaven.rbxlx   # build a place file + open it in Studio
rojo plugin install                                       # install the Rojo Studio plugin
```
Sign into Studio with the account that owns the **Louiville** experience (so publishing targets it).

## Daily loop
```bash
./scripts/studio.sh        # regenerates the LSP sourcemap, then starts `rojo serve`
```
Then in Studio: **Plugins tab → Rojo → Connect** (default `localhost:34872`). Now:
- Editing any `.luau` in `src/` **streams into Studio live** — no rebuild.
- **Play (F5)** spawns your avatar and runs the server scripts (world/house/dealership build).
- **Run (F8)** runs the sim with a free camera — good for surveying the whole map (select the
  `World`/`Dealership` folder in the Explorer and press **F** to frame it).

## The Studio MCP (optional, powerful)
A built-in **Roblox Studio MCP** is configured (`RobloxStudio` in this Claude Code project). When the
Studio-side MCP is enabled (Assistant panel → `…` → **Manage MCP Servers** → **Enable Studio as MCP
server**), the agent can drive Studio directly:
- `execute_luau` — run Luau in the live session
- `start_stop_play` + `screen_capture` + `get_console_output` — launch a playtest and *see* it
- `search_game_tree` / `inspect_instance` — explore the DataModel
- `multi_edit` / `script_read` — read & edit scripts in place

> Gotcha: the MCP is a stdio↔WebSocket proxy on port **13469**; tools only appear once Studio pushes
> them. Don't spawn the proxy by hand — let Claude Code manage it, then `/mcp` reconnect.

## Publishing
Two ways, same destination (live **Louiville**):
- **From Studio:** File → Publish to Roblox (**⌘P**).
- **From CLI:** `./scripts/publish.sh` (builds via Rojo → Open Cloud; also what the kid's agent uses).

Studio live-sync, GitHub, and the live game are **three independent targets** — syncing one doesn't
update the others. `rojo serve` updates Studio; `git push` backs up source; `publish.sh`/⌘P ships live.

## Editor (Zed)
`.zed/` is configured for Luau LSP (autocomplete, go-to-def, inlay types) + format-on-save via StyLua.
The LSP reads `sourcemap.json` — `./scripts/studio.sh` regenerates it; or run it manually after adding
files: `rojo sourcemap default.project.json -o sourcemap.json`.
